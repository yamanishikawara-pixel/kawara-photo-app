## Claude Code → 相談役への報告（現時点：計画のみ・未着手）

craft-report.jsx（`~/kawara-photo-app/craft-report.jsx`）と現行 `src/pages/BeforeAfterPage.tsx` の `A4Page` コンポーネント（報告書/印刷を担当する箇所、L62-217付近）を読み比べた。以下が実装計画。**まだ1行も実装していない。承認待ち。**

### 適用範囲についての確認

craft-report.jsx は「A4の報告書1枚」のデザイン試作であり、列挙されている変更項目（ヘッダー・番号・ラベル帯・所見・フッター）はすべて `A4Page` コンポーネント（報告書プレビュー＆印刷の見た目）に対応する。**編集フォーム側（ItemCard・写真アップロードカードのダーク UI）は対象外**と解釈した。違えば指摘してほしい。

### (1) 差し替える JSX/CSS の箇所

`A4Page` コンポーネント（`src/pages/BeforeAfterPage.tsx` 内、L62〜217）のみ。

| 箇所 | 現状 | craft-report 方向 |
|---|---|---|
| ヘッダー | 「施工前後比較」固定文言＋ページ番号のみ、高さ40px | 左：赤錆縦バー＋小見出し「施工写真報告書」＋ projectName を大きく太く。右：黒ブロックで contractorName |
| 番号 | 横並びの①②③+タイトル（titleRowH内） | 各箇所の左サイドバー（幅約132px）に「No.01」を赤錆色38px太字＋黒短線＋箇所名 |

### (2) 保存ロジックに触れない担保

- 変更対象は `A4Page` コンポーネントの JSX 構造とインライン `style` 値のみ。
- `handleSave` / `uploadImage` / `canUpload` / `trackUpload` / `deleteStorageFileWithAccounting` / `BACircleMarker`（ドラッグ・選択・サイズ・削除ロジック）/ DnD並び替え / `beforeunload` / `view` 切替 / 現場情報読み込み `useEffect` は**1行も触らない**。
- 唯一グレーゾーンなのが下記「要確認」の工期データ。それ以外はすべて既存の `item.title` / `item.beforeDesc` / `item.afterDesc` / `projectName` / `contractor` / 赤丸座標など、**既存データをそのまま別の見た目で表示するだけ**。

### (3) A4プレビューと印刷両方への反映

現行コードは `view==='report'` の画面プレビュー（`a4-preview-wrap`）と、Cmd+P 印刷専用コンテナ（`a4-print-only`）の両方が**同一の `<A4Page>` コンポーネント**を描画している（前回実装した「編集中に誤って白紙印刷されない」対策の副産物）。そのため `A4Page` 自体を直すだけで、プレビューと印刷の両方に自動的に反映される。追加の同期作業は不要。

### 要確認：フッターの「工期・元請け」について

ユーザー指示にある「工期・元請け」は、現状 `A4Page` には渡されていないデータ。調べたところ：
- **工期**：`Project` 型に `constructionPeriod` フィールドが既に存在する（表紙ページ等で使用）。`BeforeAfterPage.tsx` の現場情報読み込み箇所で `projectName` / `contractor` は取得済みだが `constructionPeriod` は取得していない。
- **元請け**：該当するフィールドが見当たらない。`contractorName`（施工業者名＝自社名）はあるが、元請け（発注元の建設会社）に相当する別フィールドは無い。craft-report.jsx のデモ文言「ナチュラル工房」はおそらく説明用の架空テキストで、実データに対応するフィールドではないと見ている。

選択肢を2つ提示する：

- **A案（推奨・最小変更）**：フッターは黒帯デザインに変更するが、中身は今まで通り「施工業者名（contractorName）＋ projectName」を表示。工期・元請けは出さない。新しい state・データ取得は一切追加しない＝「見た目だけ」を厳密に守れる。
- **B案**：`constructionPeriod` を新たに読み込んで（既存の現場情報読み込み `useEffect` に1行 `setConstructionPeriod(p.constructionPeriod ?? '')` を追加し、新しい `useState` を1つ追加）フッター左に表示する。元請けは表示できるフィールドが無いため省略する。「state は変更禁止」という制約に技術的に触れるため、この部分だけ別途明示の承認をお願いしたい。

どちらにするか指示をもらってから着手する。

### (4) 段階分け（各段階1コミット、後に `npx tsc --noEmit`、その後ユーザー実機確認）

1. **配色のベース変更**：ラベル帯の色、赤丸線色（#ff2d20→#c0492f）、番号アクセント色を新パレットに統一。構造は変えず色のみ。
2. **ヘッダーの作り替え**：左に赤錆縦バー＋ projectName 大見出し、右に黒ブロックで contractorName。ヘッダー高さ（`LAYOUT.headerH`）を40px→60〜64px程度に拡大が必要（3箇所/ページのレイアウトは維持するが、写真エリアが若干圧縮される）。
3. **番号・箇所名のサイドバー化**：横並び表記を左サイドバー（幅約132px）の「No.01」大型表記に変更。写真幅の計算式をサイドバー分差し引いて更新。
4. **所見欄の作り替え**：背景ボックス＋罫線を廃止し、左色バー1本＋本文に変更。
5. **フッターの作り替え**：黒帯デザインに変更。中身は上記A案/B案の決定に従う。

各段階の完了後、`handoff.md` のこの報告欄を更新してユーザーに見せる。保存・赤丸・印刷が無事なことを確認してから次の段階に進む。
